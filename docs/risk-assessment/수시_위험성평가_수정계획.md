# 수시 위험성평가 수정 계획

> **Version:** 1.0
> **작성일:** 2026-02-19
> **대상:** 수시 위험성평가 만들기/상세보기
> **목적:** 수시 평가에서 위험성 수준 입력 방식을 유연화하되 양식 일관성을 유지

---

## 1. 배경

현재 수시 위험성평가는 구현/연결이 제한적이며, 위험성 수준 입력 방식 요구가 다음과 같이 정리되었다.

- 수시 평가는 `상중하` 또는 `빈도강도` 중 선택 가능해야 함
- 단, 두 방식 모두 위험성평가 문서로서 공통 조치 정보가 필요함
  - 조치일(단일)
  - 조치자(최소 1인)
  - 조치확인자(최소 1인)
- 양식이 2개로 갈라지지 않도록 공통 UI 골격 유지 필요

---

## 2. 목표

1. 수시 만들기에서 위험성 수준 방식을 `상중하`/`빈도강도`로 선택 가능하게 한다.
2. 두 방식 모두 공통 조치 필드(조치일/조치자/조치확인자)를 동일하게 적용한다.
3. 화면 구조(Category > Subcategory > RiskFactor)는 동일하게 유지한다.
4. 상세보기에서 선택된 방식에 맞는 위험성 정보를 정확히 표시한다.

---

## 3. 범위

### 3.1 포함

- 수시 만들기 폼
- 수시 상세보기 렌더링
- 수시 제출 데이터 모델/검증 로직
- 수시 타입 라우팅 연결

### 3.2 제외 (후속)

- 실 API/DB 스키마 확정 및 마이그레이션
- 사용자/권한 기반 실제 인원 검색 연동
- 엑셀/PDF 출력 양식 변경

---

## 4. 핵심 설계 원칙

1. **공통 골격 고정:** 기본정보 + 작업공종 3단계 구조는 변경하지 않는다.
2. **분기 최소화:** 차이는 RiskFactor 카드의 "위험성 계산 영역"만 분기한다.
3. **공통 조치 필수화:** 조치일/조치자/조치확인자는 방식과 무관하게 필수다.
4. **문서 단위 방식 선택:** 위험성 방식은 문서 전체 기준으로 선택한다.

## 5. 데이터 모델 변경안

## 5.1 문서 레벨

```ts
type RiskMethod = 'LEVEL' | 'FREQUENCY_INTENSITY';

interface AdHocAssessmentPayload {
  // 기존 공통 필드
  siteName: string;
  companyName: string;
  approvalLineId: string | null;
  workPeriodStart: string;
  workPeriodEnd: string;
  categories: Category[];

  // 추가
  riskMethod: RiskMethod;
}
```

## 5.2 위험요인 레벨

```ts
interface RiskFactorBase {
  id: string;
  factor: string;
  improvement: string;
  workPeriodStart: string;
  workPeriodEnd: string;

  // 공통 조치 필드 (두 방식 모두 필수)
  actionDate: string;                // YYYY-MM-DD, 단일
  actionAssigneeIds: string[];       // 최소 1
  actionConfirmerIds: string[];      // 최소 1
}

interface RiskFactorLevel extends RiskFactorBase {
  level: 'HIGH' | 'MEDIUM' | 'LOW' | null;
}

interface RiskFactorFrequencyIntensity extends RiskFactorBase {
  frequency: number | null;
  intensity: number | null;
  riskScore: number | null;
  gradeLevel: '하' | '중' | '고' | null;
}
```

## 6. UI/컴포넌트 변경안

## 6.1 만들기 화면

- 상단(기본정보 하단)에 `위험성 수준 방식 선택` 추가
  - 라디오: `상중하`, `빈도강도`
- 기존 Category > Subcategory > RiskFactor 흐름 재사용
- RiskFactor 카드 구성
  - 공통: 위험요인, 개선대책, 작업기간, 조치일, 조치자, 조치확인자
  - 분기:
    - `상중하`: 위험성 수준(상/중/하)
    - `빈도강도`: 빈도/강도 입력 + 점수/등급 표시

## 6.2 상세보기 화면

- 문서의 `riskMethod` 기준으로 위험성 표현만 분기
- 공통 조치 필드는 두 방식 모두 동일 표시

---

## 7. 검증 규칙

## 7.1 공통 검증

- 대분류 최소 1개
- 각 대분류별 소분류 최소 1개
- 각 소분류별 위험요인 최소 1개
- 각 위험요인별
  - 위험요인 텍스트 필수
  - 개선대책 필수
  - 조치일 필수
  - 조치자 1인 이상
  - 조치확인자 1인 이상

## 7.2 방식별 검증

- `LEVEL`
  - 위험성 수준(`HIGH|MEDIUM|LOW`) 필수
- `FREQUENCY_INTENSITY`
  - 빈도 필수
  - 강도 필수
  - 점수/등급 계산값 유효
