# 위험성평가 최초/정기 만들기 고도화 이행 계획서

- Version: `v1.1`
- Date: `2026-02-20`
- Scope: `최초(Initial)`, `정기(Regular)` 만들기
- Constraint: 본 문서는 **구현 실행 없이 계획 수립만** 다룬다.
- Note: `v1.1`에서 대용량 저장/엑셀 생성 성능 대응 계획을 추가했다.

## 1. 배경
현재 `수시(Occasional)` 만들기에는 다음 개선이 반영되어 있다.

1. 대분류/소분류/위험요인 구간의 위험요인 버튼 UIUX 개선
2. 단계별(순차) 작성 플로우 도입
3. 사용된 대분류/소분류/위험요인 재사용 금지

동일한 작성 경험과 데이터 일관성을 위해 `최초/정기`에도 동일 정책 이관이 필요하다.

## 2. 목표
1. `최초/정기` 작성 UX를 `수시` 기준으로 정렬한다.
2. 단계별 작성 도입으로 입력 난이도와 제출 오류를 줄인다.
3. 중복 선택 방지로 데이터 품질을 높인다.

## 3. 범위
### 포함
1. 위험요인 버튼/액션 UIUX 개선 이관
2. 단계별 만들기(잠금/해제/완료/오류) 이관
3. 대분류/소분류/위험요인 재사용 금지 이관
4. 검증 메시지/제출 차단/포커스 이동 규칙 통일
5. 테스트 시나리오 확장(최초/정기)

### 제외
1. 상세보기 레이아웃 대개편
2. DB 스키마 변경
3. 모바일 전용 신규 UX 구축

## 4. 성공 기준 (Definition of Done)
1. 최초/정기 모두 단계별 플로우 정상 동작
2. 중복 선택 즉시 차단 + 사유 메시지 제공
3. 제출 차단 조건이 수시와 동일 정책으로 작동
4. 기존 저장/조회 회귀 오류 없음
5. QA 핵심 시나리오 통과율 100%
6. 장문서 저장 p95가 목표 이내(예: 3초 이하)
7. 자동저장 실패 시 사용자 재시도 UX 제공
8. 엑셀 생성은 비동기 처리로 API 타임아웃 회피
9. 엑셀 생성 실패율/지연 지표 모니터링 가능

## 5. 기준 정책
### 5.1 단계 상태
- `locked`
- `active`
- `completed`
- `error`

### 5.2 단계 순서
1. 기본정보
2. 위험성 방식(필요 시)
3. 공종/위험요인
4. 제출 확인

### 5.3 중복 금지 규칙
1. 대분류: 동일 문서 내 중복 금지
2. 소분류: 동일 대분류 내 중복 금지
3. 위험요인: 동일 소분류 내 중복 금지
4. 문자열 정규화 후 동일값 판정(앞뒤 공백, 연속 공백, 대소문자 차이)
5. 이미 사용된 항목은 선택 UI에서 `disabled` 처리(가능하면 숨김 대신 비활성 + 사유 표시)

### 5.4 성능 비기능 요구사항 (NFR)
1. 문서 저장 API p95: `<= 3s`
2. 자동저장 주기: 입력 중단 후 `1~2s debounce`
3. 자동저장 실패 재시도: 즉시 1회 + 지수 백오프 2회
4. 엑셀 생성 요청 응답: `1s 이내 Job 접수`
5. 엑셀 생성 완료 목표: 일반 문서 `<= 30s`, 대용량 문서 `<= 120s`
6. Export 실패율: `<= 1%` (주간 기준)
7. 사용자 진행 상태: `저장 중/저장됨/실패`, `엑셀 생성 중/완료/실패` 명확 표시

### 수시 구현 현황 (2025-02-20 기준)

#### ✅ 구현 완료
1. **단계별 워크플로우**
   - **3단계**: 기본/수시 정보 → 위험성 산정 방식 → 작업 공종
   - 상태: `locked` → `active` → `completed` → `error`
   - Hook: `useWorkflow` (reducer 기반)
   - 컴포넌트: `WorkflowSection`, `WorkflowProgress`
   - **통합 카드**: 기본정보 + 수시정보를 1번 섹션에서 함께 입력 ✅

2. **상태 전이 로직**
   - 섹션 잠금/해제 자동 관리
   - 완료 후 재수정 가능
   - 자동 확장/스크롤
   - 문서: `docs/risk-assessment/occasional-create-workflow-state-machine.md`

3. **중복 선택 금지**
   - 대분류: 동일 문서 내 중복 금지
   - 소분류: 동일 대분류 내 중복 금지
   - 위험요인: 동일 소분류 내 중복 금지
   - 구현: `excludedCategoryIds`, `excludedSubcategoryIds` props

4. **위험요인 UIUX 개선**
   - Empty State (대형 CTA 카드)
   - 모달 포털 처리 (`ActionAssigneeSelectModal`)
   - 위험요인 카드 스타일 통일

5. **빈도강도 개선 전/후 평가**
   - 개선 전: `beforeFrequency`, `beforeIntensity`, `beforeRiskScore`, `beforeGradeLevel`
   - 개선 후: `afterFrequency`, `afterIntensity`, `afterRiskScore`, `afterGradeLevel`
   - UI: 2열 그리드 레이아웃 (파란색/초록색 구분)
   - 검증: 각각 독립적으로 필수 검증
   - 문서: `docs/work-logs/2025-02-20-frequency-intensity-before-after.md`

## 11. 실행 시 주의 체크리스트
1. 단계 전이 로직은 폼별로 따로 구현하지 말고 공통 reducer를 우선 적용한다.
2. 중복 금지 규칙은 UI 차단과 제출 검증에서 동일 함수로 검증한다.
3. 상위 필드 변경 시 하위 데이터 처리 정책(유지+에러 vs 초기화)을 사전 확정한다.
4. 자동저장은 사용자 입력을 방해하지 않도록 debounce와 취소 가능한 요청을 사용한다.
5. 긴 문서 저장 실패를 대비해 마지막 성공 저장 시점을 사용자에게 표시한다.
6. 엑셀은 동기 다운로드 버튼으로 직접 생성하지 말고 Job 요청으로 분리한다.
7. 대용량 테스트 데이터(소분류/위험요인 다건)를 미리 준비해 성능 회귀를 방지한다.
8. 기능 플래그로 점진 적용하고 지표 이상 시 즉시 롤백 가능하게 유지한다.

## 13. 확장 시 고려사항 (주의점)

### 13.1 고정 방식 섹션 통합 관련
- 현재 최초/정기는 UI를 2단계(기본정보, 작업공종)로 노출하고, 내부적으로는 `RISK_METHOD`를 자동 완료 처리한다.
- 향후 빈도강도 방식을 최초/정기에 도입할 가능성이 있으면, `RISK_METHOD`를 완전히 제거하지 말고 "숨김/노출" 가능한 플래그 구조를 유지한다.
- 진행률/완료 판정은 화면 노출 기준(2단계)과 내부 상태 기준(3섹션)이 혼재되지 않도록, 계산 함수를 명시적으로 분리한다.

### 13.2 워크플로우 상태 안정성
- 완료 섹션 아코디언을 접었다 펼쳐도 상태가 `completed -> active`로 불필요하게 되돌아가지 않도록 이벤트 경로를 제한한다.
- "이전" 동작은 숨김 섹션으로 이동하지 않게 하고, 항상 실제 노출 섹션으로만 이동한다.
- 제출 가능 조건은 `workflow.canSubmit` 단일 값에 의존하지 말고, 화면상 필수 섹션 완료 기준을 별도로 관리한다.

### 13.3 중복 금지 규칙 확장
- 대분류/소분류/위험요인 중복 금지 규칙은 UI 차단 + 저장 전 검증 + 서버 검증(최종) 3중으로 유지한다.
- 문자열 정규화 규칙(trim, 공백 정리, 대소문자 무시)은 초기/정기/수시 전체에서 동일 함수로 재사용한다.

### 13.4 대용량 작성/저장/엑셀 생성 지연 대응
- 문서가 길어질수록 저장 요청을 "전체 덮어쓰기" 대신 "섹션/필드 단위 증분 저장"으로 전환한다.
- 자동 저장은 입력 이벤트마다 즉시 저장하지 않고 debounce(예: 800ms~1500ms) + in-flight 취소를 적용한다.
- 저장 payload는 변경분(diff)만 전송하고, 서버는 버전(optimistic lock) 기반 병합을 지원한다.
- 엑셀 생성은 동기 응답 대신 비동기 Job Queue(queued/running/success/failed)로 분리한다.
- UI는 "요청 접수 -> 생성 중 -> 완료 알림/다운로드" 상태를 명시하고, 대기 중에도 작성을 계속할 수 있어야 한다.
- 동일 문서 재요청은 캐시 키(문서 버전 + 포맷 + 필터)로 dedupe하여 중복 생성 비용을 줄인다.
- 대용량 기준(예: 위험요인 300개+, payload 5MB+)을 넘기면 자동으로 비동기 경로를 강제한다.

### 13.5 실행 전 체크리스트
- 최초/정기/수시의 생성/수정/상세에서 동일 중복 규칙이 동일 메시지로 동작하는지 확인
