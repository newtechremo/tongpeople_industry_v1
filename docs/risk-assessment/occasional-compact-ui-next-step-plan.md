# 수시 위험성평가 만들기/상세보기 컴팩트 개선 실행명세

- Version: `v1.0`
- Date: `2026-02-20`
- Goal: 화면 높이와 인지 부하를 줄이고, `작업공종(4번)` 작성 효율을 최우선으로 개선한다.

## 1. 문제 정의
1. 빈도/강도와 상중하 입력 영역이 커서 카드 길이가 길다.
2. 상단 진행률이 분리되어 있어 현재 진행 맥락 파악이 느리다.
3. 기본정보와 수시평가정보가 분리되어 초기 구간이 길어진다.
4. 아코디언을 접었다 펴면 완료 상태가 작성중처럼 보이는 상태 불일치가 있다.
5. 실제 작성의 핵심은 4번 작업공종인데, 상단 섹션이 화면을 많이 점유한다.

## 2. 정보구조(IA) 재편안
### 권장안
`1 + 2 + 3` 통합 후 `4`를 메인 영역으로 확장

1. 카드 A: `기본정보 + 수시평가정보(포함여부 포함)`
2. 카드 B: `위험성 산정 방식` (초슬림)
3. 카드 C: `작업공종` (핵심 입력 영역, 최대 공간)

### 근거
1. 수시평가정보는 미포함 케이스가 많아 별도 카드 유지 효율이 낮다.
2. 위험성 방식은 선택성 입력이라 카드 높이를 최소화할 수 있다.
3. 전체 입력 시간의 대부분이 작업공종에 집중된다.

## 3. 만들기 화면 컴팩트 규칙
1. 제목 행 우측에 진행률 배치: `수시 위험성평가 만들기 | 진행 2/3 (67%)`
2. 공통 카드 간격 축소: `space-y-6 -> space-y-3`
3. 카드 패딩 축소: `p-6 -> p-4`
4. 라벨/보조문구 1줄 우선, 긴 설명은 접기 또는 툴팁
5. 수시평가 `포함 안 함`일 때 발생일/사유 입력영역은 렌더링하지 않음
6. 4번 작업공종 카드만 기본 펼침, 상단 카드는 완료 시 자동 요약 접힘

## 4. 상세보기 화면 컴팩트 규칙
1. 기본정보/수시정보는 요약형 1줄 카드(기본 접힘)
2. 작업공종 리스트는 기본 펼침
3. 상단 요약칩 노출: `공종 수`, `소분류 수`, `위험요인 수`, `산정 방식`
4. 상세에서도 개선 전/후 비교는 2열 유지(모바일은 1열)

## 5. 아코디언 상태버그 수정 규칙(핵심)
### 5.1 상태 분리
1. `sectionStatus`: `locked | active | completed | error`
2. `sectionExpanded`: `true | false`

### 5.2 금지 규칙
1. `접기/펼치기`는 `sectionStatus`를 절대 변경하지 않는다.
2. `completed -> active` 전환은 필드 값 변경(`EDIT_FIELD`)에서만 허용한다.

### 5.3 완료 판정
1. 섹션 완료는 검증 함수 통과로만 결정한다.
2. 완료 섹션을 접어도 배지는 `완료` 상태를 유지한다.

### 5.4 상태 전이 예시
1. `CLICK_NEXT` 성공: 현재 `completed`, 다음 `active + expanded=true`
2. `TOGGLE_SECTION`: `expanded`만 반전
3. `EDIT_FIELD(완료 섹션)`: 해당 섹션 `active`, 필요 시 후행 섹션 `error/locked` 재평가

## 6. UI 와이어프레임(텍스트)
## 6.1 만들기 ✅ 구현 완료 (2025-02-20)
```text
[수시 위험성평가 만들기]                         [진행 2/3]

▼ 1. 기본/수시 정보  [완료]
  - 팀, 기간, 결재라인
  - 수시 평가 정보 (선택): 발생일, 사유
  [다음]

▼ 2. 위험성 산정 방식 [작성중]
  - 상중하 / 빈도강도 선택
  [다음]

▼ 3. 작업공종 [핵심]
  - 대분류/소분류/위험요인
  - 중복 금지 + 빠른 추가
  [제출]
```

**구현 상태**:
- ✅ 3단계 워크플로우 적용
- ✅ 기본/수시 정보 통합 카드
- ✅ 진행률 헤더 이동
- ✅ 컴팩트 UI (패딩 축소, 폰트 축소)

## 6.2 상세보기
```text
[수시 위험성평가 상세]
[공종 6] [소분류 18] [위험요인 92] [빈도강도]

▷ 기본/수시 정보 (요약 접힘)
▼ 작업공종 (기본 펼침)
```

## 7. 구현 우선순위(다음 단계)
### Step 1. 상태모델 교정 (버그 선해결)
1. `status`와 `expanded` 분리
2. 접기/펼치기 시 완료상태 유지
3. 회귀 테스트: 접기/펼치기/수정/다음 이동

### Step 2. 상단 컴팩트
1. 제목 우측 진행률 배치
2. 공통 카드 패딩/간격 축소

### Step 3. 카드 통합
1. 기본정보 + 수시평가정보를 카드 A로 통합
2. 수시정보 미포함 시 입력영역 완전 숨김

### Step 4. 4번 작업공종 집중 UX
1. 작업공종 카드의 세로 공간 우선 배분
2. 빠른 추가 CTA와 중복 차단 가시성 강화

## 8. 검증 체크리스트
1. 완료 섹션 접기/펼치기 후에도 `완료` 배지 유지
2. 값 미변경 토글만으로 `작성중`으로 회귀하지 않음
3. 수시정보 미포함 기본 흐름에서 입력 단계 수 단축됨
4. 모바일에서 레이아웃 깨짐 없음
5. 상세보기에서 작업공종 가독성 개선 확인

## 9. 결정 필요 항목
1. 진행률 계산 기준: 섹션 기반(3단계) vs 필수항목 기반
2. 카드 A 기본 상태: 완료 시 자동 접힘 여부
3. 상세보기 기본 펼침 범위: 작업공종만 vs 작업공종+수시정보
